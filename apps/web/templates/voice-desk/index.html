Voice desk: Voice In, Voice Out

Voice in, voice out: speech-to-text transcribes the audio, a model answers in spoken prose, text-to-speech reads it back. Pick local models for all three slots and the audio never leaves your machine. Each media step's error port routes to an honest failure output.

How It Works

Speech-to-text transcribes the audio, a model answers in plain spoken prose, and text-to-speech reads the answer back. Pick local models for all three and the audio never leaves your machine.

Each media step's error port routes to an honest failure output instead of a broken run. Input is an uploaded audio artifact or an audio URL; the chat's voice mode drives the same shape.

Try It

  1. In TheYgent, open Settings → Samples.
  2. Fill the model slots below with models from your registry, then click Install on Voice desk.
  3. Open the installed agent and run it with the example input.
art_<id> from POST /artifacts, or an https URL to a .wav/.mp3

What You Need

  • Speech-to-text model — A transcription model (e.g. a whisper variant) — pick a local one to keep audio on this machine.
  • Local model — Writes the spoken answer.
  • Text-to-speech model — A voice model that reads the answer back — pick a local one to keep audio on this machine. The engine's own default voice is used; set `voice` on the binding only to a name that engine actually has (voice vocabularies are engine-specific).
